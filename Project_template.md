Название: Сравнительный отчёт по LLM, эмбеддингам и векторным БД (локально vs облако)


h2. 1) LLM-модели: локальные (Hugging Face) vs облачные (OpenAI / YandexGPT)

*Критерии: качество, скорость, стоимость, развёртывание.*

| Критерий | Локальные (Llama/Qwen/Mistral из HF) | Облачные OpenAI | Облачные YandexGPT |
|---|---|---|---|
| Качество ответов | Топ-open-source (Llama 3.1/3.3 70B, Qwen3-Max, Mistral Large-instruct) в ряде задач догоняют «закрытые» модели, местами выигрывая в кодинге/узких задачах; но в среднем уступают SOTA в сложном рассуждении/мультимодальности. :contentReference[oaicite:0]{index=0} | GPT-4o/4.1 показывают стабильно высокие результаты на reasoning-бенчмарках, большие контексты и мультимодальность. :contentReference[oaicite:1]{index=1} | Коммерческие модели YandexGPT (Lite/Pro) хороши для ру/мультиязыка, но меньше публичных сравнений с SOTA; активно обновляются. :contentReference[oaicite:2]{index=2} |
| Скорость | Низкая задержка без сети (десятки–сотни мс до первого токена), но зависит от вашей GPU/CPU. Пиковая скорость стабильна и предсказуема. | Сетевая задержка + квоты провайдера; при этом токенизация/генерация обычно очень быстрая на стороне провайдера. | Аналогично: сеть + квоты; географически ближе к РФ/ЕС-регионам — потенциально ниже RTT. |
| Стоимость владения/использования | CapEx/OpEx на GPU: покупка/аренда, энергия, DevOps. Для оценки: AWS g5.2xlarge (A10G 24GB) ~ $1.21/час он-деманд. На своей GPU (например, RTX 4090) — высокая разовая стоимость, но низкая маржинальная цена за токен при стабильной загрузке. :contentReference[oaicite:3]{index=3} | Прозрачная цена за токены. Пример: GPT-4o — ~$2.5 за 1M входных и ~$10 за 1M выходных токенов. :contentReference[oaicite:4]{index=4} | Текстогенерация (YandexGPT Pro/Lite) тарифицируется «за 1000 токенов», с промо-скидкой −50% до 01.11.2025. :contentReference[oaicite:5]{index=5} |
| Развёртывание/удобство | Требует MLOps: контейнеры, ускорители, мониторинг, квантование (AWQ/GGUF), масштабирование. Гибкость 100%, офлайн/он-прем. | SDK/API за минуты, без DevOps. Богатая экосистема (функции, мультимодальность, инструменты). :contentReference[oaicite:6]{index=6} | Быстрый старт через Yandex Cloud/AI Studio, есть OpenAI-совместимые эндпоинты для некоторых моделей. :contentReference[oaicite:7]{index=7} |

Итог по LLM:
* Если нужен максимум качества/мультимодальности и минимум DevOps — облако (GPT-4o/4.1).
* Если важны данные on-prem/air-gap, кастомизация, низкая маржа на больших объёмах — локальные Llama/Qwen/Mistral с вашей GPU.
* Если оптимизируете расходы под ру-рынок и устраивает качество — YandexGPT (с учётом текущей скидки до 01.11.2025). :contentReference[oaicite:8]{index=8}

h2. 2) Модели эмбеддингов: локальные Sentence-Transformers vs OpenAI Embeddings

| Критерий | Локальные Sentence-Transformers | OpenAI Embeddings |
|---|---|---|
| Скорость создания индекса | Максимальна при наличии своей GPU и батчинге; нет сетевых лимитов. | Упираетесь в сетевую полосу и rate-limits, но масштабируемость «из коробки». |
| Качество поиска | Топ-модели из SBERT-стека (E5/BGE/ModernBERT и др.) показывают высокие результаты на MTEB/MMTEB; легко подобрать под домен и дообучить. :contentReference[oaicite:9]{index=9} | text-embedding-3-large/-small демонстрируют сильные результаты на MTEB/MIRACL, есть возможность уменьшать размерность (dimensions) без смены модели. :contentReference[oaicite:10]{index=10} |
| Стоимость | Разовая/почасовая стоимость вашей GPU. При постоянной загрузке TCO низкий, особенно при self-host. | Простая цена за 1M токенов: *text-embedding-3-small* ~$0.02, *text-embedding-3-large* ~$0.13 за 1M токенов (вход). :contentReference[oaicite:11]{index=11} |

Примечания:
* MTEB — де-факто стандарт сравнения эмбеддингов; для узких доменов (финансы/медицина) лучше ориентироваться на профильные бенчмарки (например, FinMTEB: доменно-адаптированные модели нередко превосходят универсальные). :contentReference[oaicite:12]{index=12}
* У OpenAI можно задавать меньшую *dimensions* для *text-embedding-3-large* (экономия места в индексе при умеренной потере качества). :contentReference[oaicite:13]{index=13}

h2. 3) Векторные БД: ChromaDB vs FAISS

| Критерий | ChromaDB | FAISS |
|---|---|---|
| Скорость поиска/индексации | По умолчанию использует HNSW для ANN; есть буфер «brute-force» сегмента до заливки в HNSW. Быстро для типичных RAG-нагрузок, тюнится параметрами M/ef. :contentReference[oaicite:14]{index=14} | Библиотека с богатым набором индексов (IVF, PQ, HNSW, Flat и др.), CPU/GPU-ускорение, максимально высокая производительность при ручной настройке. :contentReference[oaicite:15]{index=15} |
| Сложность внедрения/поддержки | «БД-подобный» DX: коллекции, фильтры по метаданным, хранилище и формат индексов скрыты; есть Cloud и single-node режимы. Низкий порог входа для RAG-приложений. :contentReference[oaicite:16]{index=16} | Низкоуровневая библиотека C++/Python: вы сами храните метаданные/идентификаторы, строите пайплайн, выбираете индекс/параметры/шардинг. Максимальная гибкость — цена сложностью. :contentReference[oaicite:17]{index=17} |
| Удобство в работе | Простые API (upsert/query/delete), metadata-фильтрация «из коробки», понятная структура хранения. :contentReference[oaicite:18]{index=18} | Богатая документация и гайд по выбору индекса; требует обвязки (ORM/сервер) для продакшена. :contentReference[oaicite:19]{index=19} |
| Стоимость владения (инфраструктура) | Самостоятельный сервис (Docker/коробка/Cloud Chroma). CPU-френдли, но для больших коллекций лучше SSD и/или GPU для эмбеддинга/перестроек. | Встраивается в ваше приложение; «бесплатен» как библиотека, но вам нужен собственный слой хранения/репликации/бэкапов. GPU ускоряет обучение/поиск — см. цену GPU (пример AWS g5 ~ $1.21/час). :contentReference[oaicite:20]{index=20} |

Итог по векторным БД:
* Нужен быстрый старт RAG с фильтрами/управлением коллекциями без «самопального» сервера — берите ChromaDB. :contentReference[oaicite:21]{index=21}
* Нужны экстрим-показатели скорости/памяти, продвинутые индексы, tight-integration в своё приложение — FAISS.

h2. Упрощённые рекомендации по выбору (с учётом TCO/рисков)

1) LLM:
* MVP/быстрый прод: OpenAI GPT-4o (или 4.1/4o-mini для снижения цены). Цена понятна, качество высокое. :contentReference[oaicite:22]{index=22}
* Он-прем и контроль над данными/стоимостью: Llama 3.1/3.3 70B или Qwen3-Max на вашей GPU/кластере; для кода — часто отличные результаты. :contentReference[oaicite:23]{index=23}
* Бюджетный облачный вариант для ру-сценариев: YandexGPT (с текущей скидкой). :contentReference[oaicite:24]{index=24}

2) Эмбеддинги:
* Максимум качества «из коробки» и компактные индексы — OpenAI text-embedding-3-large/small (0.13/0.02 $ за 1M). :contentReference[oaicite:25]{index=25}
* Свой домен/дообучение/офлайн — Sentence-Transformers (E5/BGE/ModernBERT и др.) + доменная донастройка по данным и валидация на профильном бенчмарке (например, FinMTEB). :contentReference[oaicite:26]{index=26}

3) Векторная база:
* Быстрый RAG без лишнего кода — ChromaDB. :contentReference[oaicite:27]{index=27}
* Максимальная производительность/контроль — FAISS (+ свой слой хранения/репликации). :contentReference[oaicite:28]{index=28}

h2. Набросок TCO-сценариев (для оценки порядка величин)

*Облако (OpenAI):*  
Пример: 10 млн вход. токенов + 2 млн вых. токенов в месяц на GPT-4o ≈ 10,000,000 * $2.5 / 1M + 2,000,000 * $10 / 1M ≈ $25 + $20 = ~$45/мес (без учёта эмбеддингов). :contentReference[oaicite:29]{index=29}

*Эмбеддинги (OpenAI):*  
50 млн токенов/мес на *text-embedding-3-small* ≈ 50 * $0.02 = ~$1.0/мес. На *-large* — ~$6.5/мес. :contentReference[oaicite:30]{index=30}

*Своя GPU (оценочно):*  
AWS g5.2xlarge по требованию: ~$1.21/час ⇒ при 120 час/мес ≈ ~$145/мес (без хранения). Постоянная 24/7 — ~$870–$900/мес; на собственной «железке» — высокая разовая цена, но низкая маржинальная стоимость при постоянной загрузке. :contentReference[oaicite:31]{index=31}

h2. Риски и организационные замечания

* Локальные LLM/эмбеддинги требуют MLOps: обновления, квантование, профилирование памяти/скорости, мониторинг качества.  
* Для облака — юридические и регуляторные вопросы (данные/регион), квоты/лимиты.  
* Для эмбеддингов всегда валидируйте «качество на вашей задаче», а не только по усреднённым MTEB-метрикам. Доменно-специфичные наборы (FinMTEB и др.) меняют картину. :contentReference[oaicite:32]{index=32}

h2. Что бы я выбрал для продакшена «здесь и сейчас»

* Если важны скорость внедрения и предсказуемое качество: GPT-4o + OpenAI Embeddings (-3-small для цены, -3-large для качества) + ChromaDB. :contentReference[oaicite:33]{index=33}  
* Если есть требования on-prem и существенный объём трафика: Llama/Qwen (HF) на вашей GPU + SBERT-совместимые эмбеддинги (E5/BGE) + FAISS (для контроля индекса) или ChromaDB (если нужен готовый «DB-UX»). :contentReference[oaicite:34]{index=34}
